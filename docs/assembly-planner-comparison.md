## 两套候选方案

本地 Codex 与本地微调装配模型是两套独立方案。它们分别接收相同的任务与语义场景，通过网站执行同一套确定性装配工具。二者不串联，不用 Codex 的通过状态代替微调模型的验证结果，也不预先指定默认胜者。未微调 Qwen 基座仅作为训练效果的对照。

两套方案共用版本化装配图、零件目录、语料快照、检索排除规则、skill、工具协议、预算和验收集。网站承担工具调用、版本检查、回滚、缓存、导出及产物记录。模型只能提出结构化操作。

## 怎样决定使用哪套方案

先比较实际执行与结构质量，再比较外观，最后考虑时间和修复成本。必须记录整车轮廓、车门与随门玻璃、轮组安装、灯罩层次、前后车身连接和机构运动。未知数据保留为未验证。导出 IO 成功、单步格式正确、训练 loss 降低都不能单独选定生产方案。

生产选择需要 Countach、F40、日产 Skyline GT-R（R34）、布加迪 Chiron Pur Sport 四款车的同输入比较与实际证据。测试家族及其重复模块不能出现在检索候选或训练集中。结果接近、关键条件失败或证据不完整时不自动更换默认方案。

`ASSEMBLY_PLANNER=codex` 与 `ASSEMBLY_PLANNER=local_finetuned` 用于分别运行。`auto` 仅在当前代码、协议和 skill 均与可重现评估报告一致时接受胜者。检查与选择实现见 `assembly_evaluation.py`；模块执行基准见 `assembly_benchmark.py`。
